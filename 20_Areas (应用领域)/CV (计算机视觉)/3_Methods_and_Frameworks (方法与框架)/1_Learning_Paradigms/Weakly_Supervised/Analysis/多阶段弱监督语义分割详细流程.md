## 1. 背景与动机

### 1.1 什么是语义分割？

语义分割（Semantic Segmentation）的目标是：对图像中的 **每一个像素** 预测其所属的类别。例如，在 PASCAL VOC 2012 数据集中，有 20 个前景类别（飞机、自行车、鸟等）+ 1 个背景类别，总共 21 类。

### 1.2 为什么需要弱监督？

全监督语义分割需要对训练图像的每一个像素都做标注（称为 **像素级标注 / pixel-level annotation**），这非常昂贵。据估计，标注一张 VOC 图像的像素掩码大约需要 **数分钟到数十分钟**。

而 **弱监督语义分割（Weakly Supervised Semantic Segmentation, WSSS）** 用更弱的标注来代替像素级标注。最常见的弱监督形式是 **图像级标签（image-level labels）**：只需要告诉模型这张图里有"猫"和"狗"，而不需要标注哪些像素属于猫、哪些属于狗。

### 1.3 为什么是"多阶段"？

由于图像级标签不包含任何空间位置信息，不可能直接得到像素级分割结果。因此，WSSS 通常采用 **多阶段（multi-stage）** 的流水线：

```
阶段 1: 图像级标签 → 生成初始 CAM（类激活图）
阶段 2: 初始 CAM → 后处理 → 伪掩码（Pseudo Mask）
阶段 3: 伪掩码当作"伪真值" → 像全监督一样训练分割模型（如 DeepLab v2）→ 最终分割结果
```

每个阶段解决一个子问题：
- **阶段 1** 解决：如何从图像级标签中获得空间位置信息
- **阶段 2** 解决：如何将粗糙的热力图转化为可用的像素级伪标签
- **阶段 3** 解决：如何利用伪标签训练一个真正的分割模型，使其泛化到测试集

## 3. 第一阶段：生成初始 CAM（类激活图）

这是整个 WSSS 流程中最核心的阶段。CLIP-ES 利用预训练好的 **CLIP（Contrastive Language-Image Pre-training）** 模型来生成 CAM，而不是从头训练分类器。

> **源代码位置**: `generate_cams_voc12.py`（VOC 数据集）和 `generate_cams_coco14.py`（COCO 数据集）

### 3.1 CLIP 模型加载与文本编码

#### 3.1.1 CLIP 模型简介

CLIP 是 OpenAI 提出的视觉-语言预训练模型。它通过对比学习，将图像和文本映射到同一个嵌入空间：

```
图像 ──→ [视觉编码器] ──→ 图像特征向量
文本 ──→ [文本编码器] ──→ 文本特征向量
```

两者在嵌入空间中相似（余弦相似度高）则表示图文匹配。

#### 3.1.2 模型加载

```python
# generate_cams_voc12.py, 第 228-229 行
model, _ = clip.load(args.model, device=device)
```

模型加载流程（`clip/clip.py` 中的 `load()` 函数）：
1. 如果是 URL → 下载到缓存目录，SHA256 校验
2. 如果是本地路径 → 直接加载
3. 调用 `clip/model.py` 中的 `build_model()` 从 state_dict 自动推断模型架构（ViT 还是 ResNet）
4. 返回 `(model, preprocess_transform)` 二元组

CLIP-ES 使用 **ViT-B/16** 架构：
- Patch size = 16×16
- 12 层 Transformer
- 隐藏维度 = 768
- 12 个注意力头

#### 3.1.3 文本特征编码

```python
# generate_cams_voc12.py, 第 230-231 行
bg_text_features = zeroshot_classifier(BACKGROUND_CATEGORY, ['a clean origami {}.'], model)
fg_text_features = zeroshot_classifier(new_class_names, ['a clean origami {}.'], model)
```

**为什么需要文本特征？**

CLIP-ES 的核心思想：不训练分类器，而是利用 CLIP 的零样本能力。将类名转换为文本特征，与图像特征做余弦相似度，就相当于"分类"。

**`zeroshot_classifier()` 函数解析**：

```python
# generate_cams_voc12.py, 第 49-60 行
def zeroshot_classifier(classnames, templates, model):
    with torch.no_grad():
        zeroshot_weights = []
        for classname in classnames:
            texts = [template.format(classname) for template in templates]
            texts = clip.tokenize(texts).to(device)          # 文本分词
            class_embeddings = model.encode_text(texts)       # 文本编码
            class_embeddings /= class_embeddings.norm(dim=-1, keepdim=True)  # L2归一化
            class_embedding = class_embeddings.mean(dim=0)    # 模板平均
            class_embedding /= class_embedding.norm()         # 再次归一化
            zeroshot_weights.append(class_embedding)
        zeroshot_weights = torch.stack(zeroshot_weights, dim=1).to(device)
    return zeroshot_weights.t()  # 返回 [num_classes, embed_dim]
```

处理流程：
1. **模板填充**：将类名填入模板 `'a clean origami {}.'`，例如 `"a clean origami cat."`
2. **分词**：使用 BPE 分词器（`clip/simple_tokenizer.py`），将文本转为 token ID 序列（长度 77）
3. **文本编码**：通过 CLIP 的文本 Transformer 编码为特征向量
4. **归一化与平均**：对所有模板结果取平均，再 L2 归一化

**类名增强（`clip_text.py`）**：

为了提高文本-图像对齐的质量，CLIP-ES 对某些类名做了增强：

```python
# clip_text.py, 第 7-12 行
class_names = ['aeroplane', 'bicycle', 'bird', ...]
new_class_names = ['aeroplane', 'bicycle', 'bird avian', ...]
# 'bird' → 'bird avian'（添加同义词）
# 'person' → 'person with clothes,people,human'（添加上下文描述）
# 'chair' → 'chair seat'
# 'tvmonitor' → 'tvmonitor screen'
```

**背景类别**：

```python
# clip_text.py, 第 1-3 行
BACKGROUND_CATEGORY = ['ground','land','grass','tree','building','wall','sky',
                        'lake','water','river','sea','railway','railroad',
                        'keyboard','helmet','cloud','house','mountain','ocean',
                        'road','rock','street','valley','bridge','sign']
```

这是 CLIP-ES 的关键设计：用多个 **背景描述词** 来编码背景区域，而不是简单地用"background"一个词。

### 3.2 图像编码与 GradCAM 计算

#### 3.2.1 图像预处理

```python
# generate_cams_voc12.py, 第 78-83 行
def _transform_resize(h, w):
    return Compose([
        Resize((h,w), interpolation=BICUBIC),
        _convert_image_to_rgb,
        ToTensor(),
        Normalize((0.48145466, 0.4578275, 0.40821073), 
                  (0.26862954, 0.26130258, 0.27577711)),
    ])
```

注意归一化参数是 CLIP 特定的，不是标准 ImageNet 参数。

图像尺寸需要是 patch_size（16）的倍数：

```python
# generate_cams_voc12.py, 第 86-93 行
def img_ms_and_flip(img_path, ori_height, ori_width, scales=[1.0], patch_size=16):
    all_imgs = []
    for scale in scales:
        preprocess = _transform_resize(
            int(np.ceil(scale * int(ori_height) / patch_size) * patch_size),
            int(np.ceil(scale * int(ori_width) / patch_size) * patch_size)
        )
        image = preprocess(Image.open(img_path))
        image_ori = image
        image_flip = torch.flip(image, [-1])  # 水平翻转
        all_imgs.append(image_ori)
        all_imgs.append(image_flip)
    return all_imgs
```

#### 3.2.2 图像编码

```python
# generate_cams_voc12.py, 第 130-131 行
image_features, attn_weight_list = model.encode_image(image, h, w)
```

CLIP 的 ViT 编码器（`clip/model.py` 中 `VisionTransformer` 类）处理步骤：

1. **Patch Embedding**：将图像分割为 16×16 的 patch，每个 patch 经过卷积投影为 768 维向量
2. **添加 CLS token**：在序列最前面添加一个可学习的类别 token
3. **位置编码**：加上可学习的位置嵌入（如果分辨率不同于预训练的 224×224，则双线性插值上采样位置编码）
4. **Transformer 编码**：经过 12 层 Transformer Block，每层输出注意力权重
5. **返回**：
   - `image_features`：最后一层的输出特征（包含 CLS token 和所有 patch token）
   - `attn_weight_list`：前 11 层的注意力权重（最后一层的注意力在后面单独计算）

#### 3.2.3 GradCAM 计算

```python
# generate_cams_voc12.py, 第 233-234 行
target_layers = [model.visual.transformer.resblocks[-1].ln_1]
cam = GradCAM(model=model, target_layers=target_layers, reshape_transform=reshape_transform)
```

**GradCAM 目标层**：选择 ViT 最后一个 Transformer Block 的 LayerNorm 层。

**GradCAM 原理**：

GradCAM（Gradient-weighted Class Activation Mapping）的公式：

$$CAM_c = ReLU\left(\sum_k \alpha_k^c A_k\right)$$

其中：
- $A_k$ 是目标层的第 $k$ 个通道的激活图
- $\alpha_k^c = \frac{1}{HW}\sum_i\sum_j \frac{\partial y^c}{\partial A_k(i,j)}$ 是类别 $c$ 对通道 $k$ 的梯度全局平均池化
- 即：以梯度的全局均值作为权重，对激活图做加权求和

**代码实现链条**：

```
GradCAM(BaseCAM)
  ├── __init__() → 创建 ActivationsAndGradients 钩子
  │     ├── save_activation() → 前向钩子，保存目标层激活
  │     └── save_gradient() → 反向钩子，保存目标层梯度
  ├── __call__() → forward()
  │     ├── ActivationsAndGradients(input_tensor) → 前向传播
  │     ├── targets[0](output).backward() → 反向传播
  │     └── compute_cam_per_layer() → 计算 CAM
  └── get_cam_weights() → np.mean(grads, axis=(2, 3))  # 核心
```

详细看 `pytorch_grad_cam/base_cam.py` 中的 forward 方法：

```python
# pytorch_grad_cam/base_cam.py 关键逻辑
def forward(self, input_tensor, targets, target_size, eigen_smooth):
    # 1. 前向传播（同时通过钩子记录激活和梯度）
    if self.compute_input_gradient:
        input_tensor = torch.autograd.Variable(input_tensor, requires_grad=True)
    outputs = self.activations_and_grads(input_tensor)  
    # outputs 包含 [logits_per_image, attn_weight]
    
    # 2. 反向传播
    self.model.zero_grad()
    loss = sum([target(output) for target, output in zip(targets, [outputs[0]])])
    loss.backward(retain_graph=True)
    
    # 3. 计算 CAM
    cam_per_layer = self.compute_cam_per_layer(input_tensor, targets, target_size, eigen_smooth)
    return self.aggregate_multi_layers(cam_per_layer), outputs[0], outputs[1]
```

**GradCAM 的核心计算**（`pytorch_grad_cam/grad_cam.py`）：

```python
class GradCAM(BaseCAM):
    def get_cam_weights(self, input_tensor, target_layer, target_category, activations, grads):
        return np.mean(grads, axis=(2, 3))
        # grads 形状: [batch, channels, H, W]
        # 对 H, W 维度取均值 → [batch, channels]
```

**reshape_transform 的作用**：

ViT 的输出是 `[序列长度, batch, 通道]` 的形式，需要转换为 CNN 风格的 `[batch, 通道, H, W]`：

```python
# generate_cams_voc12.py, 第 29-35 行
def reshape_transform(tensor, height=28, width=28):
    tensor = tensor.permute(1, 0, 2)  # [seq, batch, ch] → [batch, seq, ch]
    result = tensor[:, 1:, :]  # 去掉 CLS token，留下 patch tokens
    result = result.reshape(tensor.size(0), height, width, tensor.size(2))
    result = result.transpose(2, 3).transpose(1, 2)  # [B, H, W, C] → [B, C, H, W]
    return result
```

#### 3.2.4 核心的 perform() 函数

这是对每张图像生成 CAM 的核心函数，详细解析如下：

```python
# generate_cams_voc12.py, perform() 函数, 第 97-217 行

def perform(process_id, dataset_list, args, model, bg_text_features, fg_text_features, cam):
    # 对每张图像：
    for im_idx, im in enumerate(tqdm(databin)):
        
        # ① 读取图像信息和 XML 标注（获取图像中有哪些类别）
        img_path = os.path.join(args.img_root, im)
        xmlfile = img_path.replace('/JPEGImages', '/Annotations').replace('.jpg', '.xml')
        data = parse_xml_to_dict(etree.fromstring(open(xmlfile).read()))["annotation"]
        ori_width = int(data['size']['width'])
        ori_height = int(data['size']['height'])
        
        # ② 获取该图像中出现的类别（从 XML 标注中读取，这就是图像级标签）
        label_list = []  # 类名列表
        label_id_list = []  # 类别 ID 列表
        for obj in data["object"]:
            obj["name"] = new_class_names[class_names.index(obj["name"])]
            if obj["name"] not in label_list:
                label_list.append(obj["name"])
                label_id_list.append(new_class_names.index(obj["name"]))
        
        # ③ 图像预处理
        ms_imgs = img_ms_and_flip(img_path, ori_height, ori_width, scales=[1.0])
        ms_imgs = [ms_imgs[0]]  # 只使用原始尺度，不翻转
        
        # ④ 图像编码（获取图像特征和注意力权重）
        image_features, attn_weight_list = model.encode_image(image, h, w)
        
        # ⑤ 构建文本特征（前景类 + 背景类）
        fg_features_temp = fg_text_features[label_id_list]  # 只取该图中出现的类
        text_features_temp = torch.cat([fg_features_temp, bg_features_temp], dim=0)
        input_tensor = [image_features, text_features_temp, h, w]
        
        # ⑥ 对每个前景类别计算 GradCAM
        for idx, label in enumerate(label_list):
            targets = [ClipOutputTarget(label_list.index(label))]
            # GradCAM 前向 + 反向
            grayscale_cam, logits_per_image, attn_weight_last = cam(
                input_tensor=input_tensor, targets=targets, target_size=None)
            grayscale_cam = grayscale_cam[0, :]
            
            # 上采样到原始分辨率
            grayscale_cam_highres = cv2.resize(grayscale_cam, (ori_width, ori_height))
            
            # ⑦ 注意力亲和力精炼（详见 3.3 节）
            # ... 详见下节
            
        # ⑧ 保存结果
        np.save(os.path.join(args.cam_out_dir, im.replace('jpg', 'npy')),
                {"keys": keys.numpy(),
                 "attn_highres": refined_cam_all_scales.cpu().numpy().astype(np.float16)})
```

### 3.3 注意力亲和力精炼（Attention Affinity Refinement）

这是 CLIP-ES 相比其他 WSSS 方法的关键创新。ViT 的注意力权重天然包含像素间的语义关系，被用来 **精炼** 粗糙的 GradCAM。

```python
# generate_cams_voc12.py, 第 152-194 行

# 只在第一个类别时收集注意力权重（所有类共享同一组注意力）
if idx == 0:
    attn_weight_list.append(attn_weight_last)
    # 取所有层的注意力，去掉 CLS token 行和列
    attn_weight = [aw[:, 1:, 1:] for aw in attn_weight_list]  # (batch, HW, HW)
    # 取最后 8 层的平均
    attn_weight = torch.stack(attn_weight, dim=0)[-8:]
    attn_weight = torch.mean(attn_weight, dim=0)[0].cpu().detach()

# 步骤 1：从 CAM 中提取边界框，构建亲和力掩码
box, cnt = scoremap2bbox(scoremap=grayscale_cam, threshold=0.4, multi_contour_eval=True)
aff_mask = torch.zeros((grayscale_cam.shape[0], grayscale_cam.shape[1]))
for i_ in range(cnt):
    x0_, y0_, x1_, y1_ = box[i_]
    aff_mask[y0_:y1_, x0_:x1_] = 1  # 边界框内为 1
aff_mask = aff_mask.view(1, grayscale_cam.shape[0] * grayscale_cam.shape[1])

# 步骤 2：构建转移矩阵（双向归一化 + 对称化）
trans_mat = aff_mat / torch.sum(aff_mat, dim=0, keepdim=True)   # 列归一化
trans_mat = trans_mat / torch.sum(trans_mat, dim=1, keepdim=True) # 行归一化
# 反复归一化确保数值稳定
for _ in range(2):
    trans_mat = trans_mat / torch.sum(trans_mat, dim=0, keepdim=True)
    trans_mat = trans_mat / torch.sum(trans_mat, dim=1, keepdim=True)
# 对称化：确保 A→B 和 B→A 的亲和力一致
trans_mat = (trans_mat + trans_mat.transpose(1, 0)) / 2

# 步骤 3：自乘一次（相当于做 2 步随机游走）
for _ in range(1):
    trans_mat = torch.matmul(trans_mat, trans_mat)

# 步骤 4：用亲和力掩码限制范围（只在边界框内传播）
trans_mat = trans_mat * aff_mask

# 步骤 5：矩阵乘法精炼 CAM
cam_to_refine = torch.FloatTensor(grayscale_cam).view(-1, 1)  # (HW, 1)
cam_refined = torch.matmul(trans_mat, cam_to_refine)  # (HW, HW) × (HW, 1) → (HW, 1)
cam_refined = cam_refined.reshape(h // 16, w // 16)

# 上采样到原始分辨率
cam_refined_highres = scale_cam_image([cam_refined.numpy()], (ori_width, ori_height))[0]
```

**为什么这样做有效？**

1. **注意力权重反映语义相似性**：ViT 的自注意力机制让语义相近的区域有更高的注意力分数。
2. **随机游走传播**：将转移矩阵自乘相当于让 CAM 的激活通过注意力路径"扩散"——从种子区域扩散到语义相关但在原始 CAM 中被遗漏的区域。
3. **边界框掩码限制**：防止激活传播到完全不相关的区域（如远处的背景）。
4. **对称化**：消除注意力的方向性偏差。

### 3.4 多尺度与翻转推理

虽然当前代码中默认只使用单尺度 `scales=[1.0]` 且只取原图不翻转（`ms_imgs = [ms_imgs[0]]`），但框架支持多尺度推理：

### 4.1 CAM 质量评估

> **源代码位置**: `eval_cam.py`

这一步是可选的，用于评估生成的 CAM 的质量。

```python
# eval_cam.py, run_eval_cam() 函数, 第 45-75 行

        keys = np.pad(cam_dict['keys'] + 1, (1, 0), mode='constant')  # 0 → 背景

        # 与真值比较
        gt = np.array(Image.open(gt_file)).astype(np.uint8)

```

**背景得分的计算**：

$$bg\_score = (1 - \max_c CAM_c)^{\alpha}$$

其中 $\alpha$ 是超参数（`cam_eval_thres`）。直觉是：如果所有前景类的 CAM 值都很低，那么该像素大概率是背景。$\alpha$ 越大，背景判定越严格。

代码中的搜索策略：

**mIoU 计算**：

```python
# eval_cam.py, 第 14-38 行
def scores(label_trues, label_preds, n_class):
    # 累积混淆矩阵
    hist = np.zeros((n_class, n_class))
    for lt, lp in zip(label_trues, label_preds):
        hist += _fast_hist(lt.flatten(), lp.flatten(), n_class)
    
    # IoU = TP / (TP + FP + FN) = diag / (row_sum + col_sum - diag)
    iu = np.diag(hist) / (hist.sum(axis=1) + hist.sum(axis=0) - np.diag(hist))
    mean_iu = np.nanmean(iu[valid])
    return {"Mean IoU": mean_iu, ...}
```

### 4.2 DenseCRF 后处理

> **源代码位置**: `eval_cam_with_crf.py`

**为什么需要 CRF？**

CAM 本质上是网络内部的热力图，存在以下问题：
- **边界不精确**：CAM 的分辨率较低，上采样后边界模糊
- **噪点多**：某些背景区域可能被误激活
- **不考虑像素间关系**：CAM 独立地对每个位置做预测

**DenseCRF（全连接条件随机场）** 通过考虑像素间的 **颜色相似性** 和 **空间邻近性** 来精炼结果。

#### DenseCRF 原理简述

DenseCRF 定义了一个能量函数：

$$E(x) = \sum_i \psi_u(x_i) + \sum_{i<j} \psi_p(x_i, x_j)$$

其中：
- $\psi_u(x_i)$：**一元势**（unary potential），来自 CAM 的分类得分  
- $\psi_p(x_i, x_j)$：**二元势**（pairwise potential），编码像素对之间的关系

二元势包含两个核：

1. **外观核（Bilateral Kernel）**：
   $$k_{bi}(i,j) = w_{bi} \cdot \exp\left(-\frac{|p_i - p_j|^2}{2\sigma_{xy}^2} - \frac{|I_i - I_j|^2}{2\sigma_{rgb}^2}\right)$$
   - 空间距离近 **且** 颜色相似 → penalty 大（鼓励分配到同一类）

2. **平滑核（Gaussian Kernel）**：
   $$k_{pos}(i,j) = w_{pos} \cdot \exp\left(-\frac{|p_i - p_j|^2}{2\sigma_{pos}^2}\right)$$
   - 仅基于空间距离的平滑

#### 代码实现

```python
# eval_cam_with_crf.py, 第 14-38 行
class DenseCRF(object):
    def __init__(self, iter_max, pos_w, pos_xy_std, bi_w, bi_xy_std, bi_rgb_std):
        self.iter_max = iter_max    # CRF 推理迭代次数: 10
        self.pos_w = pos_w          # 平滑核权重: 3
        self.pos_xy_std = pos_xy_std # 平滑核空间标准差: 1
        self.bi_w = bi_w            # 双边核权重: 4
        self.bi_xy_std = bi_xy_std  # 双边核空间标准差: 67
        self.bi_rgb_std = bi_rgb_std # 双边核颜色标准差: 3

    def __call__(self, image, probmap):
        C, H, W = probmap.shape
        U = utils.unary_from_softmax(probmap)  # 将概率图转为一元势
        U = np.ascontiguousarray(U)
        image = np.ascontiguousarray(image)
        
        d = dcrf.DenseCRF2D(W, H, C)
        d.setUnaryEnergy(U)
        d.addPairwiseGaussian(sxy=self.pos_xy_std, compat=self.pos_w)      # 平滑核
        d.addPairwiseBilateral(sxy=self.bi_xy_std, srgb=self.bi_rgb_std,   # 双边核
                               rgbim=image, compat=self.bi_w)
        Q = d.inference(self.iter_max)  # 迭代推理
        Q = np.array(Q).reshape((C, H, W))
        return Q
```

**参数含义与影响**：

| 参数 | 值 | 含义 |
|------|-----|------|
| `iter_max=10` | CRF 推理 10 次迭代 | 越多越精确，但速度越慢 |
| `pos_w=3` | 平滑核权重 | 控制整体平滑强度 |
| `pos_xy_std=1` | 平滑核空间范围 | 值越大，平滑范围越大 |
| `bi_w=4` | 双边核权重 | 控制颜色相似性的影响 |
| `bi_xy_std=67` | 双边核空间范围 | 较大值允许远距离的颜色一致性 |
| `bi_rgb_std=3` | 双边核颜色敏感度 | 值越小，对颜色差异越敏感 |

    label = keys[label]  # 将局部索引映射回全局类别 ID

**置信度过滤的关键意义**：

`label[confidence < 0.95] = 255` 这一行至关重要：

- 将 CRF 输出概率低于 0.95 的像素标记为 **255**（在 VOC 中 255 表示"忽略"类别）
- 在后续的 DeepLab v2 训练中，这些 255 像素在计算 loss 时会被 **忽略**
- 这实现了 **confidence-guided loss**：只在高置信度的区域监督模型，避免错误标签带来的负面影响
- 这是 CLIP-ES 论文中的重要设计，README 中也提到了："realize confidence-guided loss by setting pixels with low confidence to 255"

## 5. 第三阶段：训练 DeepLab v2 分割模型

### 5.1 为什么需要用分割模型再训练？

你可能会问：我们已经有了 75.0% mIoU 的伪掩码，为什么还需要训练一个分割模型？直接用这些伪掩码进行推理不行吗？

答案涉及以下几个原因：

1. **泛化能力**：
   - 伪掩码是针对 **训练集每张图** 单独生成的，无法直接用于新图像
   - CLIP-ES 的 CAM 生成需要知道图像中有哪些类别（需要标签），测试时没有标签
   - 训练一个分割模型后，它学会了通用的视觉特征 → 可以在 **任意新图像** 上预测

2. **全局一致性**：
   - CAM + CRF 的结果仍然是逐图像独立处理的
   - 分割模型通过在大量训练数据上学习，获得了跨图像的统计规律
   - 模型能学到"天空通常在上方"、"道路通常在下方"等全局先验

3. **性能提升**：
   - 分割模型的架构（如 DeepLab v2 的 ASPP 模块）专门为密集预测设计
   - 模型在 VOC val set 上的 mIoU（71.1%）远超伪掩码的直接评估结果
   - 重要的是：虽然训练标签有噪声（伪掩码不完美），但深度网络有一定的 **噪声鲁棒性**

4. **效率**：
   - CLIP-ES 的推理非常慢（每张图需要 GradCAM + CRF）
   - DeepLab v2 的推理只需一次前向传播，是实时可用的

### 5.2 DeepLab v2 架构详解

> **参考仓库**: [kazuto1011/deeplab-pytorch](https://github.com/kazuto1011/deeplab-pytorch)

DeepLab v2 是 WSSS 领域最常用的分割模型（几乎所有论文都用它来保证公平比较）。

#### 5.2.1 整体架构

```
输入图像 (3, H, W)
    ↓
┌──────────────────────────────────────┐
│        ResNet-101 Backbone           │
│  (预训练于 ImageNet / COCO)           │
│                                      │
│  conv1 → bn1 → relu → maxpool       │
│  layer1 (stride=1, 256 channels)     │
│  layer2 (stride=2, 512 channels)     │
│  layer3 (stride=1*, 1024 channels)    │  ← 空洞卷积 (dilation=2)
│  layer4 (stride=1*, 2048 channels)    │  ← 空洞卷积 (dilation=4)
│                                      │
│  * Output stride = 8                 │
│  * BN 层冻结(不更新参数)              │
└──────────────┬───────────────────────┘
               ↓
┌──────────────────────────────────────┐
│    ASPP (空洞空间金字塔池化)           │
│                                      │
│  ┌─────┐ ┌─────┐ ┌─────┐ ┌──────┐  │
│  │r=6  │ │r=12 │ │r=18 │ │r=24  │  │
│  │3×3  │ │3×3  │ │3×3  │ │3×3   │  │
│  │conv │ │conv │ │conv │ │conv  │  │
│  └──┬──┘ └──┬──┘ └──┬──┘ └──┬───┘  │
│     │       │       │       │       │
│     └───────┴───────┴───────┘       │
│              ↓ (求和)                │
│         Prediction                   │
│         (num_classes, H/8, W/8)      │
└──────────────┬───────────────────────┘
               ↓
         双线性插值上采样 (×8)
               ↓
         输出 (num_classes, H, W)
```

#### 5.2.2 关键组件解释

**1. 空洞卷积（Dilated/Atrous Convolution）**

普通卷积的感受野有限。空洞卷积在卷积核的采样点之间插入"空洞"，不增加参数量就能扩大感受野：

- 普通 3×3 卷积：感受野 = 3×3
- 空洞率 r=2 的 3×3 卷积：感受野 = 5×5
- 空洞率 r=4 的 3×3 卷积：感受野 = 9×9

在 DeepLab v2 中，ResNet 的 layer3 和 layer4 原本下采样的步幅被替换为空洞卷积：
- 原始 ResNet-101：output stride = 32（即特征图为输入的 1/32）
- DeepLab v2：output stride = 8（特征图为输入的 1/8，保留更多空间细节）

**2. ASPP（Atrous Spatial Pyramid Pooling）**

ASPP 在最终特征图上并行使用 **不同空洞率** 的卷积：

```
特征图 (2048, H/8, W/8)
    ├── 3×3 conv, dilation=6  → (C, H/8, W/8)
    ├── 3×3 conv, dilation=12 → (C, H/8, W/8)
    ├── 3×3 conv, dilation=18 → (C, H/8, W/8)
    └── 3×3 conv, dilation=24 → (C, H/8, W/8)
        ↓
    求和（element-wise sum）
        ↓
    预测 (num_classes, H/8, W/8)
```

**为什么用 ASPP？** 不同的空洞率捕获不同尺度的上下文信息。小空洞率关注局部细节，大空洞率关注全局上下文。

**3. ResNet-101 Backbone 预训练**

WSSS 中通常使用两种预训练权重：
- **ImageNet 预训练**：在 ImageNet 分类任务上训练的 ResNet-101
- **COCO 预训练**：在 COCO 数据集上进一步预训练的权重（通常是完全监督分割任务的中间产物）

CLIP-ES 的 README 中提到骨干网络的预训练权重可以在 [AdvCAM](https://github.com/jbeomlee93/AdvCAM) 仓库找到。

| **学习率策略** | Polynomial decay | $lr = lr_0 \times (1 - \frac{iter}{iter_{max}})^{power}$, power 通常为 0.9 |
| **迭代次数** | 20,000 | 对于 VOC 和 COCO 10k |
| **有效 batch size** | 10 | batch_size=5, iter_size=2（梯度累积 2 次） |
| **输入尺寸** | 321×321 | 随机裁剪到固定尺寸 |
| **数据增强** | 随机缩放 [0.5, 1.5] + 随机裁剪 + 填充 | |
| **多尺度 loss** | 是 | 1x, 0.75x, 0.5x 三个尺度的 loss 求和 |
| **BN 层** | 冻结 | 不更新 Batch Normalization 参数 |
| **忽略标签** | 255 | 标记为 255 的像素不参与 loss 计算 |

#### 5.3.5 Loss 函数

DeepLab v2 使用 **多尺度交叉熵 loss**：

$$\mathcal{L} = \sum_{s \in \{1.0, 0.75, 0.5\}} CE(\hat{y}_s, y)$$

其中：
- $\hat{y}_s$ 是尺度 $s$ 下的模型预测
- $y$ 是伪掩码标签
- $CE$ 是像素级交叉熵，标签为 255 的像素被忽略

```python
# 典型的 loss 计算伪代码
criterion = nn.CrossEntropyLoss(ignore_index=255)
loss = 0
for scale in [1.0, 0.75, 0.5]:
    scaled_input = F.interpolate(input, scale_factor=scale)
    logits = model(scaled_input)
    logits = F.interpolate(logits, size=label.shape[-2:])
    loss += criterion(logits, label)
loss.backward()
```

### 5.4 DeepLab v2 的推理与 CRF 后处理

#### 5.4.1 推理

```python
# 推理伪代码
model.eval()
with torch.no_grad():
    logits = model(image)  # (1, 21, H/8, W/8)
    logits = F.interpolate(logits, size=(H, W), mode='bilinear', align_corners=False)
    prediction = torch.argmax(logits, dim=1)  # (1, H, W)
```

#### 5.4.2 推理时 CRF 后处理

与伪掩码生成阶段类似，推理时也可以对 DeepLab v2 的输出做 CRF 后处理：

```python
# 推理时 CRF

```

这通常能提升 1-2% 的 mIoU。

## 7. POT 论文的改进思路

附带的 POT（Prototypical Optimal Transport）论文是在 CLIP-ES 基础上的改进，它属于 **阶段 1 的增强**。

### 7.1 CLIP-ES 的局限性

CLIP-ES 生成的 CAM 仍然只能激活目标的 **最具区分性的区域**（如人的脸、动物的头部），而非完整区域。

### 7.2 POT 的核心改进

POT 在 CLIP-ES 的 CAM 基础上，增加了三个步骤：

1. **特征分区（Feature Partitioning）**：
   - 将 CAM 置信度高的特征用 K-means 聚类为 K 个簇
   - 每个簇有自己的原型（prototype），而非每个类一个原型

2. **特征分配（Feature Allocation）**：
   - 使用 **最优传输（Optimal Transport）** 将所有特征分配到最合适的簇
   - 引入 **相似性感知约束**：优先分配给与分类器原型更相似的簇原型

3. **特征激活（Feature Activation）**：
   - 用每个簇的更新后原型分别激活特征
   - 合并所有簇的激活结果，得到更完整的 CAM

### 7.3 效果

| 方法 | VOC CAM mIoU | VOC Mask mIoU |
|------|-------------|---------------|
| CLIP-ES（原始） | 70.8% | 75.0% |
| CLIP-ES + POT | **75.0%** | **79.3%** |

CAM 质量提升 4.2%，伪掩码质量提升 4.3%。

## 8. 常见问题 FAQ

### Q1: 为什么所有 WSSS 论文都用 DeepLab v2？

为了 **公平比较**。不同的分割架构（如 DeepLab v3+、SegFormer 等）有不同的表征能力，如果大家用不同的分割器，就无法比较谁的伪掩码更好。DeepLab v2 成为了 WSSS 社区的标准基准。

### Q2: 为什么不直接用 CLIP 做分割？

CLIP 是为 **图像级理解** 设计的，它的空间分辨率（ViT-B/16 在默认 224 输入下只有 14×14）不足以做精细的像素级分割。虽然 CLIP-ES 创新性地利用了 CLIP 的注意力来提升 CAM 质量，但最终仍需要专门的分割模型来做像素级预测。

### Q3: 训练 DeepLab v2 时伪掩码中的错误（噪声标签）怎么处理？

主要通过两种方式：
1. **置信度过滤**（label=255 的像素被忽略）：这是最直接的方式
2. **DeepLab v2 本身的正则化**：多尺度训练、数据增强、SGD 的隐式正则化等

一些更高级的方法还会引入 **共训练（co-training）**、**对抗学习** 等策略来进一步处理噪声。

### Q4: `keys` 在 CAM `.npy` 文件中的作用是什么？

因为每张图只生成 **出现在图中的类别** 的 CAM，不是全部 20 类的。`keys` 记录了 CAM 通道对应的类别 ID。例如：
- 一张图有猫（类别 7）和狗（类别 11）
- CAM 形状为 `[2, H, W]`（只有 2 个通道）
- `keys = [7, 11]` 记录通道 0 对应猫，通道 1 对应狗

### Q5: 为什么使用 `'a clean origami {}.'` 这种奇怪的模板？

这是 CLIP-ES 的设计选择。作者实验发现这个模板能产生更好的前景-背景分离效果。原因可能是：
- "clean origami" 描述的是一种简洁、清晰的视觉样式
- 这种模板帮助 CLIP 关注物体的整体形状而非纹理细节
- 避免了复杂背景的干扰

### Q6: IRN（Inter-pixel Relation Network）在某些方法中的作用？

IRN 是另一种常用的 CAM 后处理方法（来自论文 [Ahn et al., CVPR 2019]）。它学习像素间的亲和力关系来传播 CAM 的激活。在 POT 论文中提到使用 DenseCRF 和 IRN 来生成最终的伪标签。IRN 的作用类似于 CRF，但是通过神经网络来学习的。

### Q7: output stride = 8 是什么意思？

Output stride 是输入图像分辨率与最终特征图分辨率的比值。
- output stride = 8 意味着 321×321 的输入产生 ~40×40 的特征图
- 相比 output stride = 32（~10×10 特征图），保留了更多空间细节
- 这对分割任务很重要，因为边界需要精确
