# SenseNova-Vision：把传统视觉任务改写成多模态生成

论文：[Vision as Unified Multimodal Generation](https://arxiv.org/abs/2607.06560)  
官方代码：[OpenSenseNova/SenseNova-Vision](https://github.com/OpenSenseNova/SenseNova-Vision)  
模型与数据：[SenseNova-Vision Collection](https://huggingface.co/collections/sensenova/sensenova-vision)  
详细翻译与分割笔记：[SenseNova-Vision_paper_notes.md](./SenseNova-Vision_paper_notes.md)

> [!info] 这篇总结的定位
> 这不是逐段翻译，而是从“它想解决什么、基础模型是什么、怎样统一任务、训练时到底改了什么、实验能证明什么”几个问题出发重新组织论文。论文与代码直接报告的内容会注明来源；“实验解读”“价值与局限”和“我的理解”属于额外分析，不应当作论文作者的原话。

> [!note] 初学者先记住五个词
> - **UMM**：既能处理文字和图片，也能生成文字和图片的统一多模态模型。
> - **token**：模型逐个处理的一小段信息，可以来自文字，也可以来自图像小块。
> - **latent**：图片经过压缩后的内部表示，不是原始像素，也不是最终图片。
> - **任务头**：专门为检测、分割等某一种任务安装的输出模块。
> - **SFT**：拿带标准答案的数据继续训练一个已有模型，即监督微调。

## 论文分析速览

> [!abstract] 一句话结论
> **SenseNova-Vision 的核心不是发明一个新的视觉主体网络，而是证明：只要把传统视觉标注转换成 UMM 原生可生成、可解码的文本与图像目标，一个现成的统一多模态模型就能用同一组主体参数覆盖检测、OCR、分割、深度、法线与多视图 3D。** 这篇论文有力地证明了“统一多模态生成作为视觉接口”的可行性，但还没有证明它在精度、效率上全面优于专用模型，也没有证明一种任务的训练一定帮助了另一种任务。

### 核心问题与解法

传统视觉系统通常按任务拆分：检测生成框，分割生成 mask，深度估计生成逐像素标量，多视图模型预测点图和相机参数。SenseNova-Vision 不强迫这些输出全部变成同一种 token，而是利用 UMM 已有的两种原生输出通道：

- **稀疏、符号化结果走文本生成**：类别、边界框、坐标、OCR、关键点和相机位姿被序列化为文本或特殊 token，使用下一 token 交叉熵训练。
- **稠密、空间对齐结果走图像生成**：掩码、深度、法线和点图被编码成图像，经 VAE latent 与 rectified-flow 目标训练。
- **需要语义—像素绑定的任务走混合生成**：例如全景分割和 GCG（Grounded Conversation Generation，让描述中的短语与图像区域对应）先生成“实例—颜色”文字图例，再生成相应的彩色 mask。
- **自然语言指令充当任务路由器**：它同时声明要做什么、关注哪个目标，以及输出应按什么协议解码；模型主体不再为每个任务增加独立 prediction head。

因此，论文真正统一的是 **模型主体、交互接口和训练样本格式**，而不是把所有任务变成完全相同的输出、损失和评测。各任务仍保留不同的提示模板、序列化协议、图像编码、确定性后处理与基准指标。

### 主要贡献

1. **表述层贡献**：把“文本适合符号结构、图像适合稠密空间”的互补性用于统一视觉任务，比“全部文本 token 化”或“全部 RGB 化”更自然。
2. **数据层贡献**：构建 SenseNova-Vision Corpus，把大量公开标注统一转换成指令—响应样本，并公开其中 5000 万规模的 SN-VC-50M 生成/整理子集及转换规则。
3. **系统层贡献**：从 Bagel-7B-MoT 出发，不增加任务专用预测头，通过混合 SFT 同时学习四大任务族；辅助 VQA、图像生成等数据用于减轻基础能力遗忘。
4. **能力层贡献**：同一模型不仅覆盖标准基准，还展示了坐标到 mask、自由配色 mask、文字分割等由语言重新组合出来的任务变体。

### 实验应该怎样解读

| 证据 | 能支持的结论 | 不能过度推出的结论 |
| :--- | :--- | :--- |
| 结构化视觉理解在多个检测、OCR、GUI 与关键点基准上很强 | 文本生成接口可以稳定承载多类稀疏视觉记录 | 所有长序列、极密集目标场景都已解决 |
| 深度和法线接近或超过多种生成式基线 | UMM 的图像生成先验适合空间对齐的稠密任务 | 已全面超过几何专用模型；部分训练答案由 MoGe-2 等模型生成，成绩也会继承这些模型的先验 |
| 推理分割表现突出，但通用/指代分割多项落后 X-SAM 等模型 | 语言理解与 mask 生成的组合是其长项 | 生成式 mask 已替代 SAM、Mask2Former 一类专用 mask decoder |
| 多视图重建和位姿在 generalist 路线中有竞争力，但仍落后最强专用模型 | 文本/图像原生输出能够扩展到 3D 几何 | 模型已经学到完整而稳定的显式 3D 世界模型 |
| MMVP 从 Bagel 的 83.3 降到 79.0，GenEval 从 0.82 升到 0.85 | 混合训练大体保留图像生成能力，并显著增加视觉任务覆盖 | “能力保持”是无损的；视觉理解仍出现约 4.3 分下降 |

> [!important] 论文证明了什么
> 它较有说服力地给出了一个 **existence proof（存在性证明）**：单个 UMM 可以通过原生文本、图像和混合生成空间，产出覆盖 2D 感知、稠密几何和多视图 3D 的可评测结果。论文最有价值的不是某一个榜单第一，而是展示了一条把传统 CV 监督吸收到通用基础模型中的工程路径。

> [!warning] 论文还没有证明什么
> - **缺少关键消融（逐项去掉某个设计的对照实验）**：没有同预算的单任务训练、分任务预测头、去除某类数据、去除辅助多模态数据或不同分辨率的系统对照，因此无法判断收益究竟来自“统一表述”、超大规模数据、Bagel 预训练，还是由其他模型生成的训练答案。
> - **跨任务重组主要是定性证据**：坐标到 mask、自由颜色、文字分割等案例很有启发性，但样本少、没有系统成功率，尚不足以证明稳定的零样本任务泛化。
> - **比较并非完全同条件**：不同模型的训练数据、提示、分辨率、后处理和部分深度评测协议不同；表 5 更适合说明能力覆盖面，而不是作为严格排行榜。
> - **“无任务头”不等于“无任务工程”**：相机位姿需要保留特殊 token，分割需要调色板和颜色解析，坐标与稠密图也各有编码/解码规则。复杂性从专用网络头部分转移到了数据协议和后处理。
> - **效率与可靠性证据不足**：正文没有完整报告训练硬件、推理采样步数、延迟、吞吐与随机性。对于需要实时、确定性输出和锐利边界的场景，生成式路径未必比一次前馈的专用模型合适。

### 我的总体评价

这是一篇 **方向价值高于单项算法新颖性** 的工作。它把 UMM 从“能看图、能画图”推进到“可以把经典视觉监督当作原生生成任务学习”，其意义类似于把视觉任务从一组 API 重新组织成一种可由语言编程的能力空间。最值得借鉴的是输出模态分工与数据协议设计，而不是某个新的网络模块。

当前版本更像统一视觉系统的强基线，而不是专用 CV 模型的终结者：如果目标是边界精度、可校准置信度、确定性和实时性，专用检测/分割/几何模型仍更可靠；如果目标是一个模型通过语言临时组合任务、跨文本与像素输出协作，SenseNova-Vision 所代表的路线更有潜力。

## 1. 基础模型到底是什么？

SenseNova-Vision **不是从零训练的模型，基模也不是另一个 SenseNova 模型**。论文明确写明，它从字节跳动 Seed 开源的 [Bagel-7B-MoT](https://github.com/ByteDance-Seed/Bagel) 检查点开始训练。

Bagel 是统一多模态模型（UMM），不是单纯的文生图模型，也不是只能看图回答文字的 MLLM。它在一个 decoder-only、多模态生成框架中处理文字和视觉 token，原本就具有：

- 图像理解与视觉问答；
- 文本生成；
- 文生图和图像编辑；
- 文字—图像交错输入输出。

Bagel 使用 MoT（Mixture-of-Transformer-Experts）提高不同模态的建模容量；根据 [Bagel 官方说明](https://github.com/ByteDance-Seed/Bagel/blob/a2fa77dd8caeefc41e6607ae0ec17408d3f4ee9f/README.md#L55-L63)，它共有 14B 参数，每次前向计算激活约 7B 参数。它还使用两条视觉编码路径：语义理解侧使用 ViT/SigLIP，视觉生成侧使用 VAE latent。SenseNova-Vision 正是利用了 Bagel 已经具备的文本和图像生成通道，而不是重新造一套检测器或分割器。

> [!note] 通俗类比｜这是“专业再训练”，不是“重新造大脑”
> Bagel 原本像一个既会看图、写字，也会画图的通才。SenseNova-Vision 的做法，是把检测、OCR、分割、深度和 3D 等任务整理成它已经能读写的“文字答题卡”和“图片答题卡”，再进行大规模混合任务训练。模型没有为每门课安装一个新的专用脑区，但训练数据、答题格式和评分规则都经过了大量工程设计。

### 1.1 它与几条相关路线有什么区别？

| 路线 | 代表性模型 | 基本做法 | 与 SenseNova-Vision 的差别 |
| :--- | :--- | :--- | :--- |
| 把视觉答案序列化 | Pix2Seq v2、OFA、Unified-IO、Florence-2 | 尽量把类别、框、点甚至稠密结果写成 token 序列 | 符号结果很自然，但精细 mask 容易变成长序列；SenseNova-Vision 让稠密结果走图像生成 |
| 用图像生成做稠密预测 | Marigold、Lotus、DICEPTION | 把深度、法线或分割图当成要生成的图像 | 擅长空间对齐结果，但类别、OCR 和相机参数等符号记录不自然 |
| MLLM 外接任务模块 | LISA、X-SAM 等 | 语言模型理解任务，再把信息交给专用 mask decoder | 通常有较强 mask 先验，但仍保留任务专用解码路径 |
| 原生统一多模态生成 | Bagel、Janus、Show-o 等 | 模型本身就支持文字和视觉生成 | SenseNova-Vision 在这类基模之上，把传统 CV 监督系统地接入两种原生输出空间 |

论文的定位并不是否定这些路线，而是尝试解决它们之间尚未统一的问题：**怎样在同一个原生生成接口中同时容纳符号记录、稠密空间图和文字—图像混合答案。**

## 2. 图 3：整个系统怎样工作？

**图 3：SenseNova-Vision 把异构视觉标注转换为原生文本、图像或文本—图像混合目标，并在一个 UMM 中联合训练。**

这张图可以先记成四块：**下方给材料，中间同一个模型处理，上方用三种形式回答，右侧说明怎样训练。**

再看颜色和箭头：**蓝色代表文字，绿色代表视觉；下方箭头是输入，上方箭头是答案；输入图片旁的小编号与顶部同编号的任务相对应。**

### 2.1 下方：输入和三类 embedding

- **`Image Emb.`**：输入图经 SigLIP2/ViT 语义编码器后得到的一组 patch 表示，偏向理解“图里有什么、分别在哪里”。它不是只剩一个整图向量，而是一串保留局部位置的图像 token。
- **`Text Emb.`**：文字指令中各 token 的表示，用来告诉模型要完成什么任务、关注哪个目标以及按什么格式回答。
- **`Visual Emb.`**：VAE 把图像压缩成的空间 latent。它最初更像 `[C,H',W']` 形式的缩小版多通道特征图，随后按小块展开成一串带二维位置的视觉 token，**不是经过 GAP 后得到的单个全局向量**。

最通俗的记法是：`Image Emb.` 像帮助模型认东西的“读图笔记”，`Visual Emb.` 像帮助模型保存和生成局部画面的“压缩草稿”。这里的 GAP 是全局平均池化，也就是把整张特征图汇总成一个向量；官方实现没有这样处理 `Visual Emb.`。

`Image Emb.` 和 `Visual Emb.` 的差别主要不在于“一个有空间、一个没空间”，因为二者都保留局部 token；差别在于作用：

- `Image Emb.` 更偏语义理解；
- `Visual Emb.` 更偏保留可重建的局部空间与生成信息。

对于分割等图像条件生成任务，官方数据加载代码会让同一输入图同时进入 `vit_image` 和 `vae_image` 路径，见 [`seg_dataset_jsonl.py`](https://github.com/OpenSenseNova/SenseNova-Vision/blob/4366e0e1f4d22d2207ecc8e339f886b765ba876e/data/seg_dataset_jsonl.py#L165-L174)。VAE latent 在进入统一模型前保留高宽、被分块展开并加入位置编码，见 [`bagel.py`](https://github.com/OpenSenseNova/SenseNova-Vision/blob/4366e0e1f4d22d2207ecc8e339f886b765ba876e/modeling/bagel/bagel.py#L570-L584)。

### 2.2 中间：一个统一生成主体

图中央只有一个 SenseNova-Vision 主体。检测、OCR、分割、深度和多视图 3D 共享这套生成模型；任务差异主要由指令、目标模态和解码协议表达。

这里的“统一”不是说所有任务都使用同一种损失，而是说它们共享主体模型和生成接口：文字 token 与视觉 latent 可以在同一序列和同一优化过程中出现。

### 2.3 上方：三种回答形式

| 图中区域 | 输出形式 | 代表任务 | 为什么这样输出 |
| :--- | :--- | :--- | :--- |
| A：蓝色 | 文本或结构化 token | 检测、指点、指代定位、关键点、OCR、相机位姿 | 类别、坐标和字符串属于稀疏的符号记录 |
| B：蓝色 + 绿色 | 文字与图像交错 | 全景分割、GCG 分割 | 文字说明区域和颜色含义，彩色 mask 保存每个像素的位置 |
| C：绿色 | 图像型视觉输出 | 深度、表面法线、指代/交互分割、点图 | 答案需要与输入图逐位置对齐 |

> [!note] `Visual Emb.` 与 `Visual Output` 不要混淆
> `Visual Emb.` 泛指 VAE 视觉通道里的局部 latent token。图 3 把它画在下方，是在强调它可以承载输入图的生成条件；上方的 `Visual Output` 才是最终生成的深度图、mask 或点图。训练视觉输出时，正确答案图也会先经 VAE 变成同类 latent，再加噪并接受 rectified-flow 监督；推理时则从噪声逐步生成 latent，最后由 VAE 解码成图像。

### 2.4 右侧 Training Design

| 图中设计 | 初学者理解 |
| :--- | :--- |
| Heterogeneous Data | 混合不同 CV 任务和通用 UMM 数据，而不是只训一种任务 |
| High Resolution | 语义编码器最高使用 980 像素条件；图中还标出 latent 编码尺度 1024，这些是分辨率尺度，不是 embedding 维数 |
| Multi-View | 一个样本可输入 2～10 个视图，用于点图和相机位姿 |
| Unified Decoder | 不为检测、分割、深度等任务分别添加专用预测头 |
| Joint Supervision | 文字使用 CE，视觉 latent 使用 rectified-flow 目标，并在同一训练过程中优化 |
| Interleaved V+L | 一次回答可以原生交错出现文字和视觉结果 |
| Retain General Abilities | 混入 QA、VQA、文生图和图生图数据，缓解基础能力遗忘 |

## 3. 四大任务族如何放进同一接口？

| 任务族 | 它回答的问题 | 典型输出 |
| :--- | :--- | :--- |
| 结构化视觉理解 | 有什么、在哪里、写了什么 | 类别、框、点、关键点、OCR、布局、GUI 坐标 |
| 稠密几何预测 | 每个像素的距离或表面朝向是什么 | 深度图（离相机多远）、表面法线图（表面朝向） |
| 分割 | 哪些像素属于指定目标或区域 | 二值 mask，或文字图例 + 彩色 mask |
| 多视图视觉几何 | 多张图中的场景结构和相机怎样对应 | 3D 点图（每个像素对应的三维坐标）、相机位姿 token（相机的位置和朝向） |

SenseNova-Vision 没有强迫所有答案都变成文字。它选择了一种更自然的分工：

- 框、点、OCR 和相机参数适合写成文字或特殊 token；
- mask、深度、法线和点图适合生成图像；
- 既需要类别说明又需要像素位置的任务采用文字—图像混合输出。

### 3.1 五类分割任务的区别

| 任务 | 用户提供什么 | 模型先判断什么 | 输出 | 最短理解 |
| :--- | :--- | :--- | :--- | :--- |
| 指代分割（RefSeg） | “黑脸的羊”等明确文字描述 | 这段话指向哪个实例 | 二值 mask | 根据明确描述切出一个目标 |
| 推理分割（ReaSeg） | “什么东西可以用来切蛋糕”等间接问题 | 先推断答案是什么，再定位目标 | 二值 mask | 先猜出要找谁，再切出来 |
| 交互分割（InterSeg） | 点、框、涂鸦或已有 mask | 空间提示属于哪个完整物体 | 二值 mask | 用户先指一下，模型补全区域 |
| 通用分割（Gen. Seg.） | 用户给定类别清单 | 找出清单中的所有区域和实例 | 颜色图例 + 彩色 mask | 按题目给的清单为整图上色 |
| GCG 分割 | 开放式描述要求 | 自己组织区域描述，并把短语绑定到像素 | 描述 + 颜色图例 + 彩色 mask | 边描述图片，边指出描述内容在哪里 |

**通用分割和 GCG 的关键区别**：通用分割的类别清单由用户预先给出；GCG 的指令更开放，模型还要自己生成区域描述。二者都可能输出全图彩色 mask，但文字部分承担的任务不同。

## 4. 什么是“可解码的目标响应”？

这里的“目标”是训练时的标准答案（target），不是目标物体。“可解码”表示回答遵循固定协议，程序能够把它还原成传统视觉任务所需的数据结构。

例如：

- 例如示意格式 `<p>猫</p><bbox>[0.1,0.2,0.5,0.8]</bbox>` 可以还原成类别和边界框；实际坐标含义和字段顺序以具体任务模板为准；
- 黑白生成图可以还原成二值 mask；
- 灰度图可以按约定换算成深度；
- 彩色 mask 配合 `<color>` 图例可以还原各类别和实例；
- 相机位姿 token 可以还原成旋转、平移方向和尺度参数。

完整链路是：

```text
传统 CV 标注
→ 转换成固定格式的指令—答案
→ 模型学习生成文字 token 或视觉 latent
→ 程序按协议解码
→ 检测框、mask、深度图、点图或相机位姿
```

这也是论文中最容易被低估的工作：任务头虽然没有了，但大量复杂性被移动到了数据转换、任务模板、输出协议和后处理。

> [!note] `SN-VC-50M` 不是“5000 万张互不相同的照片”
> 论文把它称为约 5000 万 example 的生成与整理子集。同一来源图像可以因为任务或目标不同形成不同训练样本；附录表 19 又使用 `Frames` 作为统一计数单位，一张静态图片、一个视频帧或多视图场景中的一个视角都可以计为一帧。因此 `50M examples`、原始图片数和表中的帧数不是同一个统计口径，也不表示这些数据全部来自视频。

> [!note] `<SEG>` 在这里是什么？
> SenseNova-Vision 训练数据中的 `<SEG>` 更像“这里应该插入一张分割结果图”的占位符。官方 [`SegJSONLIterableDataset`](https://github.com/OpenSenseNova/SenseNova-Vision/blob/4366e0e1f4d22d2207ecc8e339f886b765ba876e/data/seg_dataset_jsonl.py#L175-L195) 读到它后，会加载 `seg` 字段指向的 mask 图片，并把目标图登记成需要视觉生成损失的 [`vae_image`](https://github.com/OpenSenseNova/SenseNova-Vision/blob/4366e0e1f4d22d2207ecc8e339f886b765ba876e/data/seg_dataset_jsonl.py#L73-L100)。它不像 LISA 那样把 `<SEG>` 位置的 hidden state 送给外接 mask decoder；真正的监督目标是 mask 图像的 VAE latent。

## 5. 训练：它确实是在做混合任务微调

论文把训练称为 **mixed-task fine-tuning**。它不是从头预训练一个 UMM，而是从 Bagel-7B-MoT 检查点出发，进行监督微调（SFT）。

### 5.1 混合了哪些数据？

训练数据包括：

1. **SenseNova-Vision Corpus**：检测、OCR、关键点、稠密几何、分割和多视图几何等转换后的 CV 样本；
2. **通用多模态数据**：VQA、文生图、图生图等，用来尽量保留 Bagel 原有的开放式理解和生成能力。

训练器从加权混合中抽取样本，一个 mini-batch 可以同时包含多个任务类别。因此“混合任务”并非先把检测训完再训分割，而是不同任务和不同输出模态在同一个优化过程中交错出现。

### 5.2 两类 loss 怎样分工？

| 输出 | 训练目标 | 典型任务 |
| :--- | :--- | :--- |
| 文本 token | 下一 token 交叉熵（CE） | 检测框、OCR、关键点、相机参数 |
| VAE visual latent | Bagel 原有的 rectified-flow 目标 | mask、深度、法线、点图 |
| 文字 + 图像 | 两类目标共同出现 | 全景分割、GCG 分割 |

两个目标在共享模型参数处汇合，但它们并没有被强行变成同一个数学损失。“统一”指的是共享模型、序列和训练过程。

### 5.3 哪些参数更新？

论文明确说明：

- **VAE 模型本身不参与参数更新**：论文表述为冻结 VAE visual encoder；[公开实现](https://github.com/OpenSenseNova/SenseNova-Vision/blob/4366e0e1f4d22d2207ecc8e339f886b765ba876e/train/pretrain_unified_navit.py#L536-L547) 实际将整个 `vae_model` 的参数设为不训练。不过，`vae2llm`、`llm2vae` 等视觉生成连接/投影层仍属于可更新的统一模型；
- **LLM、ViT 与连接器继续更新**：公开代码中的 `freeze_llm` 和 `freeze_vit` 默认均为 `False`，见[训练参数定义](https://github.com/OpenSenseNova/SenseNova-Vision/blob/4366e0e1f4d22d2207ecc8e339f886b765ba876e/train/pretrain_unified_navit.py#L319-L334)；
- 训练 50K 步，其中 500 步 warm-up；
- AdamW 学习率为 $2.5\times10^{-5}$，不使用权重衰减；
- 使用 0.995 EMA，评测采用 EMA 检查点；
- 其余配置沿用 Bagel 的 SFT 阶段。

所以这更接近一次大范围原有参数参与更新的 SFT，而不是只训练一个小型 LoRA 或任务头。统一模型中的 CE 与视觉 flow-velocity MSE 计算见 [`modeling/bagel/bagel.py`](https://github.com/OpenSenseNova/SenseNova-Vision/blob/4366e0e1f4d22d2207ecc8e339f886b765ba876e/modeling/bagel/bagel.py#L218-L286)。

> [!warning] 论文配置与当前开源训练脚本并非逐项相同
> 上面的 50K 步是论文第 4 节报告的实验设置；当前仓库的 [`train_cv_unify.sh`](https://github.com/OpenSenseNova/SenseNova-Vision/blob/4366e0e1f4d22d2207ecc8e339f886b765ba876e/scripts/train_cv_unify.sh#L55-L72) 设置为 200K 步，而学习率、500 步 warm-up 和 0.995 EMA 与论文一致。论文写多视图训练每个场景最多选 10 个视图，当前默认开源配置中的 [`camera_pose_sft`](https://github.com/OpenSenseNova/SenseNova-Vision/blob/4366e0e1f4d22d2207ecc8e339f886b765ba876e/data/configs/cv_unify/cv_unify_baseline_v9.yaml#L933-L971) 则设置为 8～12 帧。官方 README 将公开训练管线描述为针对开源数据适配的版本，因此不能用当前脚本和配置反推论文原始训练设置。

## 6. 到底有没有改变模型结构？

最准确的回答是：**没有增加任务专用预测头，也没有改变 Bagel 的基本统一生成架构；但是改变和扩展了训练配置、词表用途、数据接口与推理解码。**

- **网络结构**：沿用 Bagel 主体和原生文字/视觉生成接口，没有新增各任务专用头。
- **模型参数**：除固定的 VAE 外，大量原有参数会在混合 SFT 中更新，所以“结构没变”不等于“模型没怎么训练”。
- **工程接口**：数据格式、输入分辨率、多视图、特殊 token 和结果解码均有适配。

| 基本没有改变的部分 | 确实做了适配的部分 |
| :--- | :--- |
| Bagel 的统一 decoder-only / MoT 主体 | 将异构标注转换成统一指令—响应格式 |
| ViT/SigLIP 语义理解路径 | SigLIP2 输入条件最高提高到 980 像素 |
| VAE visual latent 生成路径 | 一个样本随机选取最多 10 个多视图输入 |
| 文本 CE 与视觉 rectified-flow 两类原生目标 | 重用基础模型词表最后 2,009 个条目表示相机位姿：2,001 个编码 `[-1000,1000]` 的量化值，8 个作为结构标记 |
| 原生文本/图像交错生成能力 | 为每项任务设计提示、序列化、解析与后处理 |

论文所说的“no architectural changes”不能解释成“官方代码与 Bagel 完全相同”。例如高分辨率 NaViT 式输入、多视图数据组织、相机位姿 token 和各种数据加载器都需要实现工作。它更准确地表示：**作者没有再外挂 detection head、mask decoder、depth head 或 pose head。**

## 7. 实验结果说明了什么？

### 7.1 四类任务的总体表现

- **结构化视觉理解**：整体最强，尤其在密集、小目标、长尾、指代和 OCR 定位任务上表现突出，说明文本序列可以有效承载结构化视觉记录。
- **稠密几何**：在多个深度和法线基准上超过近期生成式基线，并接近几何专用模型；但部分训练目标由 MoGe-2 补全或生成，因此不能把全部能力归因于统一训练本身。
- **分割**：在推理分割上很强，GCG 和框提示交互分割也有竞争力；但通用分割、指代分割等指标仍常落后于 X-SAM 等带专用 mask 先验的方法。
- **多视图几何**：在通用模型中表现较强，但与 VGGT、Depth Anything 3 等专用前馈几何模型相比仍有差距。

### 7.2 是否保住了 Bagel 的原有能力？

论文只给出有限但有代表性的对照：

- MMVP：Bagel 83.3，SenseNova-Vision 79.0；
- GenEval：Bagel 0.82，SenseNova-Vision 0.85。

准确地说，模型在 **GenEval 这一项**没有下降，反而提高了 0.03；在 **MMVP 这一项**下降了 4.3 分。这两个数字只能说明对应基准上的变化，不能代表所有图像生成与多模态理解能力。因此论文所说的“保留核心通用能力”可以成立，但不能进一步写成“完全无损”或“所有原有能力都得到保留”。

### 7.3 最有趣的证据不是排行榜

论文展示了一些训练协议中没有被逐项枚举的组合任务：

- 把文本坐标直接用于交互分割；
- 用检测能力支持稠密实例 mask；
- 用自由语言指定 mask 颜色；
- 把 OCR 定位与 mask 生成组合成文字分割。

这些例子说明共享的文本—空间—视觉生成接口可能让不同任务知识重新组合。但它们主要是定性案例，尚不能证明模型对任意新任务都能稳定零样本泛化。

## 8. 这条路线的价值与局限

### 8.1 真正有价值的地方

1. **输出模态分工合理**：没有为了形式统一而强迫所有 mask 变成长文本，也没有强迫类别和坐标都画成 RGB 图。
2. **把数据协议提升为核心设计**：研究重点从“每个任务造一个头”转向“怎样把监督变成基础模型原生可读写的格式”。
3. **便于语言组合任务**：任务、目标、颜色和输出格式都能由指令临时指定。
4. **提供了大规模工程证据**：一个现成 UMM 确实可以吸收横跨 2D、分割、稠密几何和多视图 3D 的监督。

### 8.2 仍然存在的问题

- **生成速度与随机性**：视觉结果需要迭代采样，通常比一次前馈的专用预测头慢，也可能在重复推理时产生变化。
- **VAE 瓶颈**：细线、小字、小目标和锐利边界经过 latent 压缩与解码后可能变粗或模糊。
- **协议脆弱性**：文字实例数、颜色图例和 mask 颜色必须一致，任何一环出错都会影响最终解码。
- **置信度不透明**：生成图像没有天然的每像素类别概率，难以像传统分割模型那样直接校准置信度。
- **缺少关键消融**：论文没有充分拆解数据规模、Bagel 预训练、统一协议与多任务共享各自贡献了多少提升。
- **专用模型内置的任务结构仍有价值**：在精确边界、实时性和几何一致性上，专用模型仍可能更强、更稳定。

## 9. 这种规模的统一模型应该怎样研究？

> [!note] 我的理解｜个人不需要把所有任务都学成专家
> SenseNova-Vision 覆盖的每个任务都足以形成独立研究方向，现实中通常会由团队分工：有人负责模型与训练系统，有人负责数据协议与清洗，有人负责分割或几何等任务族，有人负责评测、部署和效率。论文作者列表较长，也反映了这类统一系统的协作性质。
>
> 对个人研究者而言，更可行的切入方式不是“彻底掌握全部任务”，而是抓住一个横向问题，例如：统一输出协议是否优于专用头、多任务之间是否真的正迁移、VAE 为什么损伤边界、怎样约束文字图例与 mask 一致、怎样让视觉生成推理更快。理解整个系统的接口，再深入其中一个问题，就已经可以形成有价值的研究。

## 10. 最终结论

SenseNova-Vision 可以概括为：

```text
现成的 Bagel 统一多模态生成模型
+ 大规模可解码的 CV 指令—响应语料
+ CV 与通用多模态数据的混合 SFT
+ 高分辨率、多视图和任务协议适配
= 一个能以文字、图像或二者混合回答多种视觉任务的统一模型
```

它最大的贡献不是创造一种新的 backbone，而是提出并验证了一种组织计算机视觉监督的方法：**让语言负责说明“做什么、找什么、每个区域代表什么”，让图像生成通道负责保存“每个像素在哪里”，再让同一个基础模型共同学习两者。**

这条路线尚未取代专用视觉系统，但它展示了一个重要方向：未来的视觉基础模型可能不再通过不断增加任务头扩展能力，而是通过更统一、更可编程的输入输出协议吸收新的视觉监督。
