# 笔记项目框架

## 目录职责与入口

按内容要解决的问题选择主目录，一份内容只保留一个主文件，用内部链接连接其他主题。

| 位置 | 存放内容 | 入口 |
|---|---|---|
| `00_Meta (元数据)` | 组织规则、标签、写作模板与提示词 | [标签规范](标签规范.md)、[通用模板](note_template.md)、[论文模板](paper_notes_template.md) |
| `10_Knowledge_Base (知识库)` | 可复用的数学、机器学习、深度学习概念、模型机制与研究算子 | [知识库](../10_Knowledge_Base%20(知识库)/_Knowledge_Base_Hub.md) |
| `20_Areas (应用领域)` | CV、NLP 中的任务、方法、论文与领域分析 | [应用领域](../20_Areas%20(应用领域)/_Areas_Hub.md) |
| `30_Projects (项目实践)` | 代码实现、训练实验、框架教程、部署和实践记录 | [项目实践](../30_Projects%20(项目实践)/_Projects_Hub.md) |
| `40_Exploration (知识探索)` | 新领域初识、跨方向调研、概览与长期问题 | [知识探索](../40_Exploration%20(知识探索)/_Exploration_Hub.md) |
| `99_Assets (资源文件)` | 论文 PDF、插图、截图及其他被笔记引用的附件 | [资源目录](../99_Assets%20(资源文件)/) |

知识、领域、实践、探索和资源形成五层内容结构；元数据目录负责维护这些内容的使用规则。

知识库沿用 `1_Math (数学基础)`、`2_ML_Concepts (机器学习概念)`、`3_DL_Core_Concepts (深度学习核心概念)`、`4_DL_Models_And_Mechanisms (模型与机制)` 和 `5_Research_Operators (研究算子库)`。研究算子按可复用操作组织，入口为 [Research Operators](../10_Knowledge_Base%20(知识库)/5_Research_Operators%20(研究算子库)/_Research_Operators_Hub.md)。

CV 沿用 `1_CV_Theory (理论)`、`2_CV_Models (模型)`、`3_Methods_and_Frameworks (方法与框架)` 和 `4_CV_Topics (专题研究)`。方法归档遵循 [方法与框架规则](../20_Areas%20(应用领域)/CV%20(计算机视觉)/3_Methods_and_Frameworks%20(方法与框架)/README.md)。专题 Hub 通过链接和标签连接分散的相关内容，不复制论文正文。

## 归档决策

1. 通用公式、机制或可复用操作放知识库；以某篇论文为主线的方法分析放应用领域。
2. 面向领域任务的理论与方法放对应 CV/NLP 目录。CV 基石模型解释放 `2_CV_Models (模型)`；具体研究方法按任务设定进入方法目录。
3. 实验、框架用法、代码运行与部署放项目实践。源码学习笔记沿用已有论文或项目位置，不为了统一目录移动既有文件。
4. 初次了解某个方向、尚未形成专门研究主线或跨领域的问题梳理放知识探索。探索可以长期保存，篇幅、成熟度或存放时长都不构成必须迁出的条件。
5. 图片和 PDF 优先复用资源目录中的现有文件；沿用同目录笔记的图片链接习惯，不为目录整齐搬动附件。

优先复用现有目录。只有已有内容确实形成独立、持续使用的主题时才考虑新增子目录；不要先创建一批空目录或空白主题笔记。

## 命名与内部链接

- 既有文件保留路径和文件名。新增内容沿用相邻笔记风格，如 `{方法名}_paper_notes.md`、`{方法名}_Translation.md`、`{方法名}_code_notes.md` 或清楚的概念名；探索可用 `{主题}_overview.md`。
- Hub 使用 `_主题_Hub.md`；不要把 Hub 和普通主题页写成同一类型。
- Obsidian 内部关联可用 `[[实际文件名]]`；重名时补充仓库内路径。面向 GitHub 的导航使用相对 Markdown 链接，路径中空格可编码为 `%20`。
- 新增链接前确认文件或资源实际存在；缺失来源可写文字说明，不造占位链接。保留已有图片路径和外部来源链接。
- 静态可点击入口放在 Hub 前部，Dataview 聚合放在后部。目录全景应包含无元数据笔记；主题动态列表排除 `hub-note`、`map-of-content` 及页面自身。

## 元数据的适用范围

核心知识笔记使用文件开头的真实 YAML Frontmatter，最小字段为 `type`、`tags`、`status`。核心范围包括知识库中的概念、机制、算子笔记，以及应用领域中的主要论文和方法分析。

```yaml
---
type: concept-note
tags: [attention, transformer]
status: in-progress
---
```

译文、附录翻译、随手记、资料占位、教程和代码笔记不强制补信息卡片。判断范围要看笔记用途和内容，不能只看 `type`。探索笔记的卡片可选，可使用 `overview-note`；不加卡片也可以由静态导航或目录全景收录。

- `type` 描述笔记用途：如 `concept-note`、`paper-note`、`operator-note`、`concept-comparison`、`hub-note`、`map-of-content`、`overview-note`。保留既有合法类型，不仅因目录或篇幅批量改型。
- `tags` 使用平铺英文小写，词组用连字符，按 [标签规范](标签规范.md) 选择；缩写可保留小写形式。`cv`、`nlp` 只在主题适用时使用，不是所有笔记的必填标签。
- `status` 只描述整理进度：`todo`（待整理）、`in-progress`（整理中）、`done`（本轮整理完成）。它不表示知识正确性、研究价值或理解深浅，不因正文长短重判既有状态。新增核心卡片默认 `in-progress`，新 Hub 可用 `done`，模板可用 `todo` 或 `in-progress`。
- 已有 `aliases`、`model`、`year`、`paper_year` 和其他有意义的自定义属性均保留；标签小写规则不适用于模型名、别名或标题。

新论文卡片用字符串 `venue` 表示可确认的发表来源，如 `CVPR2026`；尚未确认正式发表则如实写 `arXiv` 或已知 arXiv 标识。不新增 `year` 字段，不推测会期或年份。

```yaml
---
type: paper-note
tags: [semantic-segmentation, weakly-supervised, wsss]
status: in-progress
model: 方法名
venue: CVPR2026
---
```

年份查询依次使用有效的四位整数 `year`、有效的四位整数 `paper_year`、`venue` 中唯一明确的四位年份；`venue` 包含多个不同年份时留空。明确的 `arXiv:YYMM.NNNNN` 且月份为 `01` 至 `12` 时，可按 `20YY` 读取年份。无法确定时留空，保留原始文献信息。

## 模板与提示词

- [通用笔记模板](note_template.md)：需要较完整方法解释时使用。
- [论文翻译与精读模板](paper_notes_template.md)：约束翻译、原文保留与理解性 note。
- [探索概览模板](overview_note_template.md)：可选的简短起点，按内容需要增删。
- [知识探索提示词](exploration_prompt.txt)：输入主题或已有材料，联网核实并整理包含前置知识、必要公式与配图的知识笔记。
- [论文工作流 PromptV4](PromptV4.txt)：论文翻译、精读、源码学习与算子补充。
- [元数据提示词 V2](metadata_promptV2.txt)：仅处理适用笔记的开头信息卡片，正文保持原样。
- [归档目录](Archive%20(归档)/)：保存提示词历史版本，供回查；日常使用以上现行模板与提示词。
